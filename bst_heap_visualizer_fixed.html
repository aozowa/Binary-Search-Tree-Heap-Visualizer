Tree and heap rules

Binary search tree (BST)

A BST organizes values so searching can skip parts of the tree. For every node, values smaller than it go in the left subtree and values greater than it go in the right subtree. This rule applies at every node. To build one, insert values in order: start at the root, compare each value, move left if smaller or right if larger, and place it in the first empty spot. To search, make the same comparisons from the root until you find the value or reach an empty child.

Example: insert 50, 30, 70. The 30 goes left of 50; 70 goes right.

Min heap

A min heap is a complete binary tree (all levels filled except possibly the last, which fills left to right) where each parent is less than or equal to its children. The smallest value is at the root. A heap does not require left-to-right sorted values.

Max heap

A max heap is also complete, but each parent is greater than or equal to its children. The largest value is at the root.

How to solve / heapify

  1. Check the tree shape: a heap must be complete.
  2. Start at the lowest parent and move upward.
  3. For a min heap, compare each parent with its children and swap with the smaller child if needed. For a max heap, swap with the larger child.
  4. Continue swapping down that branch, then move to the next parent. Finish at the root.
  5. For root removal, replace the root with the last (deepest, rightmost) value, remove that last node, then sift the new root down using the same min/max rule.

This visualizer heapifies the values while keeping the input tree links fixed. The usual array-based heap also relies on complete-tree shape.
